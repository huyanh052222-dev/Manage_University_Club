1.1. Bản chất và Mục tiêu Dự án:
- Dự án là hệ thống Dashboard quản lý và theo dõi vận hành 8 quán café sinh viên
  thuộc Câu lạc bộ Sinh Viên (gồm các quán từ Team A đến Team H: The Vortex Coffee,
  Chuột Ôm Cheese Coffee, AUREXA Coffee, Tabulous Beasts, Ngự Hoa Viên, The Ora
  café, 7-Byte Brew, Fortuna).
- Mục tiêu: Minh họa và theo dõi hoạt động kinh doanh giả lập/thực chiến: doanh
  thu, chi phí vận hành hàng tuần, quỹ tiền mặt (coin), uy tín (1-5 sao), nhân sự,
  và phân bổ đơn hàng đồ uống hàng tuần.
- Nền tảng kỹ thuật hiện tại:
  + Frontend: Vanilla HTML5, CSS3 thuần (Tokens, Flexbox/Grid), JavaScript ES Modules.
    Không sử dụng Node.js package build (không có package.json, không bundler).
  + Backend as a Service: Supabase (PostgreSQL, Supabase Auth, Row Level Security,
    các hàm Stored Procedure / RPC viết bằng PL/pgSQL).
  + Deployment: Static hosting trên Vercel qua cấu hình định tuyến vercel.json.

[!] ĐIỂM SỬA 3: Lỗ hổng bảo mật và lộ lọt dữ liệu tài chính qua chính sách RLS
- Hiện trạng:
  + File `scripts/supabase/supabase.js` công khai `supabaseKey` (anon key). Điều này
    là chuẩn với client-side frontend.
  + Tuy nhiên, trong `scripts/supabase/schema.sql`, chính sách bảo mật tầng dòng

    `create policy "public_read_coin_transactions" on public.coin_transactions for select to anon, authenticated using (true);`

    tiền của toàn bộ các quán khác.
- Cần sửa: Điều chỉnh RLS policy trên Supabase:
  + Chỉ cho phép anon đọc dữ liệu public của quán (tên, logo, sao, danh sách thành viên).

    * Bảng `coin_transactions`: Tự động chèn dòng giao dịch mới vào bảng nhật ký
      kèm hiệu ứng highlight xanh/đỏ sinh động.

[+] TÍNH NĂNG 5: Cơ Chế Gamification & Đánh Giá Của Khách Hàng (Feedback/Rating)

  + Cấp độ quán (Level Up): Quán đạt mốc XP nhất định sẽ được nâng cấp bậc, mở

4. NHỮNG ĐIỂM CẦN UPDATE (REFACTORING, HIỆN ĐẠI HÓA & TỐI ƯU HỆ THỐNG)

[^] UPDATE 1: Hiện Đại Hóa Môi Trường Phát Triển & Công Cụ Build (Build Tooling)
- Vấn đề: Dự án dùng Vanilla JS nạp qua thẻ `<script type="module">` với hàng loạt
  query string thủ công để chống cache (ví dụ: `?v=20260923-reputation-supabase-v1`).
  Cách làm này thủ công, dễ quên đổi phiên bản dẫn đến lỗi cache trên máy người dùng,
  và không tận dụng được các thư viện npm hiện đại.
- Giải pháp đề xuất:
  + Giữ nguyên cấu trúc code hoặc nâng cấp lên Vite + Vanilla JS (hoặc Vite + React/Vue).
  + Tận dụng Vite để tự động bundle, minify code, tối ưu asset, tự động sinh content hash
    cho các file tĩnh (`main.[hash].js`), loại bỏ hoàn toàn việc gõ `?v=...` thủ công.

[^] UPDATE 2: Bảo Mật Biến Môi Trường (.env)
- Vấn đề: `supabaseUrl` và `supabaseKey` đang bị gán cứng (hardcode) trực tiếp
  trong mã nguồn `scripts/supabase/supabase.js`.
- Giải pháp: Đưa các thông số này vào file `.env` (ví dụ `VITE_SUPABASE_URL`,
  `VITE_SUPABASE_ANON_KEY`) và cấu hình Environment Variables trên Vercel. Không
  commit trực tiếp secret key lên git repo công khai.

[^] UPDATE 3: Chuẩn Hóa và Hợp Nhất Bộ Migration SQL (Database Schema Consolidation)
- Vấn đề: Thư mục `scripts/supabase/` hiện có tới 11 file SQL rời rạc, chắp vá qua
  nhiều lần sửa đổi:
  (`schema.sql`, `weekly_deduction.sql`, `monday_revenue_cycle.sql`,
   `correct_opening_capital_revenue.sql`, `manual_coin_revenue.sql`,
   `late_settlement_adjustments.sql`, `manual_deduction_settlement.sql`,
   `reputation_sync.sql`, `add_coin_reason.sql`, `settlement_log_reason_patch.sql`,
   `rename_cafes.sql`).
  Người mới triển khai rất dễ chạy thiếu file hoặc chạy sai thứ tự dẫn đến lỗi thiếu cột,
  thiếu hàm RPC.
- Giải pháp:
  + Gộp lại thành 1 file duy nhất: `00_baseline_schema.sql` chứa toàn bộ bảng, cột,
    ràng buộc, chính sách RLS và toàn bộ phiên bản mới nhất của các hàm RPC
    (`add_points_to_team`, `set_team_reputation`, `refresh_late_financial_settlement`,
     `assign_income_transactions_to_late_settlement`, `deduct_weekly_coins`, v.v.).
  + Đưa vào tài liệu thứ tự cài đặt rõ ràng 1-click.

[^] UPDATE 4: Đồng Bộ Thư Viện Biểu Tượng (Icon System) & Tối Ưu Tải Trang
- Vấn đề:
  + Landing page dùng inline SVG từ file `scripts/components/icons.js`.

- Giải pháp: Đồng bộ toàn bộ icon trong dự án về một nguồn duy nhất (sử dụng SVG inline
  hoặc bộ icon mã nguồn mở như Lucide Icons / Heroicons).

[^] UPDATE 5: Tùy Biến Ảnh Đại Diện (Hero Cover) Riêng Biệt Cho Từng Quán
